# Android native build — CNG, R8 and the custom scheme

Branch: `feature/android-native-build` · Delivery: `ask-on-risk` · Runner: `pnpm test` + Gradle
Objective: prove the native Android layer that Expo Go never exercised — the config-plugin output, the custom scheme, and a minified release build under R8.

## Specs

- **S1 — Package identity.** `apps/mobile/app.json` sets `expo.android.package` to `com.seventeenlabs.aquisuena`. Android requires every identifier segment to start with a letter (`[a-zA-Z][a-zA-Z0-9_]*`), so the literal reverse-DNS `com.17labs.*` is invalid. One identifier serves both platforms; it is permanent after the first Play Store publish.
- **S2 — CNG.** `apps/mobile/android/` and `apps/mobile/ios/` are generated by `expo prebuild` and never committed. They are listed in `.gitignore`; the native project stays derived from `app.json` plus config plugins.
- **S3 — Prebuild output.** `expo prebuild --platform android` generates `applicationId com.seventeenlabs.aquisuena`, an `aqui-suena` VIEW/BROWSABLE intent filter from the `expo-router` plugin, and `android.enableMinifyInReleaseBuilds=true`.
- **S4 — Debug build.** `expo run:android` compiles and installs the native app, and a cold `aqui-suena:///` launch opens `MainActivity` with `Status: ok`.
- **S5 — Release build under R8.** `expo run:android --variant release` produces an APK that runs `minifyReleaseWithR8`, embeds `assets/index.android.bundle`, boots without Metro, and completes the player flow (status, listener count, station switch).
- **S6 — Cleartext boundary.** The release build cannot reach a plain-HTTP API because `targetSdk 36` blocks cleartext by default. The finding is recorded, and the production endpoint requirement (HTTPS) is documented instead of weakening the manifest.

## Log

- **L1 — 2026-10-19, user request (verbatim):**
  > User approved proceeding; if code or configuration will change, do it on a new git branch to avoid breaking main.
- **L2 — 2026-10-19, package id decision.** Android's application-id rule ("Each segment must start with a letter", `developer.android.com/studio/build/application-id`) rejects `com.17labs.aquisuena` because the `17labs` segment starts with a digit. Chose `com.seventeenlabs.aquisuena`: valid on Android, reusable as the iOS bundle identifier, and it leaves `com.seventeenlabs.*` free for other 17Labs apps.
- **L3 — 2026-10-19, prebuild.** `expo prebuild --platform android --clean` generated the project. `AndroidManifest.xml` carries the `aqui-suena` VIEW/DEFAULT/BROWSABLE intent filter; `app/build.gradle` resolves `applicationId 'com.seventeenlabs.aquisuena'`; `gradle.properties` sets `android.enableMinifyInReleaseBuilds=true`; the release build type signs with the debug keystore, so a local release build needs no keystore. `expo-localization` contributes nothing: its plugin only writes `CFBundleLocalizations` / `android:localeConfig` when `supportedLocales` is configured, and `app.json` passes none.
- **L4 — 2026-10-19, debug variant.** Gradle debug build succeeded (~17 min, first run downloads and compiles CMake targets). `pm dump` shows the scheme registered on `com.seventeenlabs.aquisuena/.MainActivity`; the RN dev-server autodiscovery permission dialog appears in debug only. Cold launch with `am start -W -a android.intent.action.VIEW -d "aqui-suena:///"` returned `Status: ok`, `LaunchState: COLD`, and the app rendered the full landing. SDK 58's new `__expo_url` launch contract was delivered through the custom scheme.
- **L5 — 2026-10-19, release variant.** `:app:minifyReleaseWithR8` and `:app:assembleRelease` succeeded (~38 min first run); R8 produced a 63 MB `mapping.txt`. The APK embeds `assets/index.android.bundle` (3.7 MB) and boots cold in 585 ms with `adb reverse` removed, so Metro is not involved.
  - First release run showed `Signal unavailable, trying mirror...`: the release manifest has no `usesCleartextTraffic` and `targetSdk 36`, so Android blocks `http://10.0.2.2:3000`. This is the correct production behavior, not a defect — the production stream endpoint must be HTTPS.
  - To prove the player path under R8 anyway, `usesCleartextTraffic="true"` was added to the generated (gitignored) `android/app/src/main/AndroidManifest.xml`, the release APK rebuilt in 6 min 43 s, and the patch reverted afterwards. With it: playing status, 42 listeners, and a station switch Test Pop → Test Night that kept playing, with no JS or native errors in logcat.
  - `EXPO_PUBLIC_*` is inlined at bundle time: the release build bakes the API base URL, so it must be passed to the build command (`EXPO_PUBLIC_STREAM_BASE_URL=http://10.0.2.2:3000` for the emulator) and never changed at runtime.
- **L6 — 2026-10-19, follow-ups observed, not fixed in this slice.** `expo-localization` is declared as a plugin with no `supportedLocales`, so it is inert: either configure the locale list or drop the plugin. The Gradle daemon warns about 2 GiB heap / 512 MiB metaspace; long builds survive it by restarting the daemon.
